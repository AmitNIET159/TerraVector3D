# Integration Guide — BhuDrishti Geospatial AI

## Purpose
How the master backend integrates with this module

## Python Imports
```python
from src import (
    normalize_geojson,
    analyze_floor_plan,
    detect_floor_levels,
    generate_synthetic_pointcloud,
    calculate_confidence,
)
```

## FastAPI-Ready Function Call Examples
```python
from fastapi import FastAPI, UploadFile
from src import normalize_geojson, analyze_floor_plan

app = FastAPI()

@app.post("/api/normalize-parcel")
async def normalize_parcel(parcel_path: str):
    result = normalize_geojson(parcel_path)
    return result  # already JSON-serialisable

@app.post("/api/analyze-floor-plan")
async def analyze_plan(image_path: str, metres_per_pixel: float = None):
    result = analyze_floor_plan(image_path, metres_per_pixel=metres_per_pixel)
    return result
```
Note: these examples show how the functions integrate — the module itself does NOT include a FastAPI server.

## Accepted File Types
| Function | Input Type | Format |
|---|---|---|
| normalize_geojson | GeoJSON file | .geojson (Polygon/MultiPolygon) |
| analyze_floor_plan | Image file | .png, .jpg |
| detect_floor_levels | Point cloud | .ply |
| generate_synthetic_pointcloud | Output path | .ply (generated) |
| calculate_confidence | Python dict | {factor: score} |

## Expected JSON Output

**`normalized_parcel.json`**:
- `parent_ulpin`, `footprint`, `area_sqm`, `bounding_box`, `coordinate_reference`, `source_type`, `confidence_score`, `warnings`, `human_verification_required`, `disclaimer`

**`floor_plan_suggestions.json`**:
- `parent_ulpin`, `coordinate_reference`, `image_path`, `metres_per_pixel`, `proposed_units` (array of: `proposed_unit_code`, `proposed_boundary`, `area_px`, `area_sqm`, `metric_area_available`, `confidence_score`, `label_suggestion`, `warnings`, `human_verification_required`), `warnings`, `human_verification_required`, `disclaimer`

**`pointcloud_floor_suggestions.json`**:
- `parent_ulpin`, `coordinate_reference`, `method_used`, `detected_slab_elevations_m`, `estimated_floor_height_m`, `suggested_levels` (array of: `level_code`, `slab_z_m`, `z_min_m`, `z_max_m`, `point_count`, `confidence_score`, `warnings`, `human_verification_required`), `warnings`, `human_verification_required`

**`confidence_result.json`**:
- `overall_score`, `confidence_level`, `factor_breakdown`, `available_sources`, `missing_sources`, `explanation`, `warnings`, `human_verification_required`

## Vertical ID Integration
Vertical IDs are NOT generated by this module. The separate bhudrishti_identity_rights module owns all vertical-ID generation and validation. This module outputs proposed_unit_code, proposed_level_code, proposed_boundary, and source_confidence which are consumed by bhudrishti_identity_rights to produce final vertical IDs.

## Cross-Module Data Contract
- `coordinate_reference`: "LOCAL_METERS" everywhere
- `parent_ulpin`: exactly 14 uppercase alphanumeric characters
- Demo ULPIN: 7A4B9C2D8E1F6G
- All snake_case field names

## SIH Presentation Limitations

> **IMPORTANT**: AI suggestions require authorised human verification before use in any cadastral or ownership workflow.

- All outputs are prototype decision-support only
- This module uses fictional/synthetic data for demonstration
- Floor-plan analysis uses classical OpenCV (no deep learning model)
- Point-cloud detection uses three local methods (histogram, RANSAC, DBSCAN) — none require downloaded model weights
- No real cadastral data, coordinates, or property records are used
- No cloud services, paid APIs, or internet access required
- Confidence scores are estimates based on available data quality
- The module does not perform legal boundary validation

## Master Backend Integration Flow
```
1. Backend receives upload (GeoJSON / image / PLY)
2. Backend calls normalize_geojson() / analyze_floor_plan() / detect_floor_levels()
3. Backend calls calculate_confidence() with scores from step 2
4. Backend passes proposed data to bhudrishti_identity_rights for vertical-ID assignment
5. Backend presents results to human operator for verification
6. Human operator approves/rejects/modifies
7. Backend stores verified result
```
